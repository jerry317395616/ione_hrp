# 审批委托

## 目标

`HRP Delegation` 扩展 COD-025 的声明式审批矩阵，在用户休假或临时分工期间转移具体审批责任。
它只改变审批解析结果中的责任人，不执行批准、不改变 Frappe Workflow 状态，也不写目标业务单据。

## 数据模型

- 委托锁定 `matrix`、`matrix_revision` 和 `matrix_digest`；矩阵修订后旧委托不再参与解析；
- 法人、医院、组织单元及是否包含下级均从矩阵复制，调用方不能扩大范围；
- `step_sequence` 留空时只覆盖该矩阵中委托人实际拥有的全部步骤，填写时只覆盖指定步骤；
- 有效期包含起止日，最长 366 天；状态为 `Scheduled`、`Active`、`Revoked` 或 `Expired`；
- 策略字段创建后不可修改，撤销和到期仅改变生命周期字段并保留审计时间。

## 创建规则

1. 委托人必须真实拥有矩阵中的用户或角色审批步骤；
2. 非系统管理员只能为自己创建和撤销委托；
3. 委托双方必须是启用的 System User，并具有目标 DocType 写权限及 COD-024 组织写范围；
4. 自我委托、重叠委托、转委托链、循环和同一责任的多个受托人均默认拒绝；
5. 创建与撤销必须携带 `Idempotency-Key`，并在单一数据库事务内完成；
6. 任何直接插入、修改或删除 DocType 的操作均拒绝。

## 审批解析

解析器仅加载当前日期有效、未撤销、与矩阵修订及摘要一致的委托。即使每日状态同步任务尚未执行，
已到开始日期的 `Scheduled` 委托也立即有效；过期日期条件始终优先阻止使用。受托人在每次解析时
重新验证目标 DocPerm 和组织范围，权限被收回后默认失败而不是继续授权。

返回的审批步骤以受托人替换原审批人，并附加 `delegated_from` 与 `delegation`；顶层返回稳定排序的
`delegations` 列表。审计仅记录策略摘要、矩阵修订、状态和数量，不记录用户名或组织原值。

## API 与 Desk

- `CORE-008`：幂等创建审批委托；
- `CORE-030`：幂等撤销审批委托；
- `CORE-031`：管理员、审计员或委托双方只读查询；
- “权限与授权”工作区提供审批委托列表、新建对话框、撤销操作和“审批委托与超期清单”报表。

## 调度、迁移与回滚

每日任务激活计划委托并标记过期委托；运行时日期过滤不依赖该任务准点执行。迁移仅新增委托表、
两个复合索引、角色和工作区元数据。生产部署前必须完整备份数据库、公开文件、私有文件和站点配置。
回滚代码时保留委托记录，不删除表；旧代码不会消费这些数据。紧急停用时撤销有效委托或停用对应矩阵。

## 验证

纯测试覆盖日期、摘要、步骤替换和歧义；Frappe 集成覆盖元数据、索引、权限、幂等、重叠、矩阵修订、
撤销、调度、真实审批解析和 Guest HTTP 边界。仓库契约强制运行模型、蓝图、目录、API 与文档一致。
