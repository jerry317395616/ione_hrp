# 审批矩阵解析器

## 目标

`HRP Approval Matrix` 按目标 DocType、法人、医院、组织单元、生效日期、优先级、金额和声明式业务维度，
确定性生成审批步骤。它只解析审批责任，不代替 Frappe Workflow，也不直接提交、批准或修改目标单据。

## 数据模型

- 矩阵主表保存稳定编码、适用组织、生效期、额外维度、优先级、修订号和策略摘要；
- 步骤子表保存连续序号、起始金额、角色或指定用户、`All`/`Any` 会签模式；
- 同一序号可配置多个并行审批来源，但名称、阈值和会签模式必须一致；
- 第一阶段从金额 0 开始，后续阈值单调不减，最多 100 行；
- 矩阵身份字段不可修改，修订通过乐观锁递增，删除默认禁止。

## 解析规则

1. 调用方必须具有目标单据读权限，并命中同一单据的组织访问范围；
2. 请求中的法人、医院、组织单元、日期、金额和业务维度必须与真实单据一致；
3. 只选择当前有效、启用、维度匹配且覆盖组织单元的矩阵；
4. 最高优先级只能有一个候选，歧义时拒绝而不是猜测；
5. 只激活起始金额不大于单据金额的连续步骤；
6. 审批人必须是启用的 System User，同时具有目标单据写权限和匹配的组织写范围；
7. 任一激活步骤没有审批人时拒绝；
8. 输出按步骤、用户和来源排序，并生成稳定 `decision_digest`。

## 安全边界

业务维度只允许最多 16 个小写字段名和文本值。策略不能配置字段表达式、SQL、Python、Server Script、
`eval` 或 `exec`。组织字段由代码与 DocType 元数据决定；调用方不能通过请求覆盖。策略解析只读，写接口
必须携带 `Idempotency-Key`，所有读写均产生不含组织值和用户名的摘要审计。

## API

- `CORE-002`：只读评估真实单据，不需要幂等键；
- `CORE-028`：管理员幂等创建或修订矩阵；
- `CORE-029`：管理员和审计员读取矩阵定义。

## 迁移与回滚

迁移创建两张表和三个复合索引，并同步“权限与授权”工作区。正式部署前必须完整备份数据库及文件。
回滚代码时保留矩阵与步骤数据，不执行破坏性删除；紧急停用策略时将矩阵设为禁用。
