# ADR-0005 使用应用生命周期钩子建立请求与后台任务审计上下文

## 背景与问题

`ione_hrp` 已在模块启停、变更治理和工程脚本中分别生成关联 ID，但规则、长度
和允许字符不一致。HTTP 请求、受控错误和后台任务之间也没有统一的父子关系，
日志只能定位单次错误，无法证明多个执行属于同一业务调用。直接修改 Frappe
核心可以全局植入上下文，但会违反上游锁定与可升级边界；把上下文保存为可编辑
DocType 又会引入数据库写入、清理周期和可篡改的第二份真相。

## 决策驱动因素

- 关联 ID 必须跨 HTTP、服务调用和后台任务保持不变。
- 每次 HTTP 请求或任务执行必须获得新的请求 ID，不能复用调用方提供的请求 ID。
- 非法或敏感输入不得进入响应、日志或目标后台函数。
- 审计日志不得记录用户、邮箱、患者、请求正文、文件路径、站点或凭据。
- Frappe v17 锁定版本原生提供请求和任务前后钩子，应用无需修改上游源码。
- 失败响应、成功响应和后台任务必须使用同一个上下文来源。

## 备选方案

1. 修改 `frappe.app` 和后台任务执行器：覆盖最彻底，但破坏上游锁定、Press 更新
   和单应用边界。
2. 建立 `HRP Audit Context` DocType：可查询历史，但每个请求都会写库，存在隐私、
   容量、清理和篡改风险，也不能在数据库连接失败前提供上下文。
3. 使用 `ione_hrp` 的 `before_request`、`after_request`、`before_job`、
   `after_job` 钩子和不可变内存模型，审计历史只写结构化脱敏日志：无需修改上游，
   可覆盖请求与任务，并保持失败关闭。

## 决策

采用方案 3。`AuditContext` 固定包含 schema 版本、`correlation_id`、
`request_id`、可空的 `parent_request_id` 和执行通道。调用方只可提供严格校验的
`correlation_id`；`request_id` 始终由服务端生成。HTTP 参数保持对历史接口请求头
的优先级，随后上下文不可被替换。响应固定返回 `X-Correlation-ID` 和
`X-Request-ID`。

后台任务只能通过 `enqueue_with_audit` 传播最小载荷。`before_job` 在调用目标
函数前弹出载荷，生成新的请求 ID，并把上游请求 ID保存为父 ID。非法载荷被丢弃
并替换为安全上下文，不传递给业务函数。所有自研应用审计必须经过
`emit_audit_event`，只接受受控事件名和标量字段。

不经过请求或任务钩子的最外层服务入口通过 `service_audit_scope` 建立短生命周期
上下文；退出时清理，嵌套调用则复用且不可替换。该规则防止 Bench、控制台与安装
流程在同一进程内连续执行时串用上一条服务上下文。

## 后果

HTTP 和任务日志可按关联 ID 聚合，又能用请求 ID精确定位单次执行。应用钩子会
作用于安装了 `ione_hrp` 的整个 Frappe Site，因此这是关键级变更；非法自定义
关联头会返回统一的 400 错误。队列传播需要调用公开服务，直接使用
`frappe.enqueue` 的既有代码只能得到新的任务上下文，不能自动继承父 ID。

本决策不创建 DocType、Fixture、Patch、Workspace 或业务数据，也不写
`GL Entry`、`Stock Ledger Entry`、`Bin` 或已提交标准单据。

## 验证与退出条件

纯单元测试必须验证标识符、载荷、父子关系、字段脱敏和确定性；锁定 Bench 集成
测试必须验证 HTTP 成功、Guest、非法头、响应头、错误体、只读幂等、队列传播和
非法载荷。仓库门禁必须禁止重复关联 ID 正则、旁路请求头读取和直接
`frappe.logger`。若锁定 Frappe 提供等价的标准跨请求与任务上下文，可由新 ADR
取代本决策。

## 迁移与回滚

无数据库迁移。发布后旧接口仍接受原 `correlation_id` 参数，新增响应头和错误体
字段为向后兼容扩展。回滚时整体移除四个应用钩子、上下文服务和新增 API，并恢复
原调用点；不删除业务数据、不重写审计历史，也不修改上游应用。

## 安全与合规

调用方提供的值仅允许受控 ASCII 字符且最长 140 字符；请求 ID 不接受外部输入。
公开上下文不含用户、角色、IP、URL、请求正文或站点名。日志字段名按敏感标记
失败关闭，值只允许短标量；嵌套对象、控制字符和非有限数字被拒绝。非法后台
载荷不会中断 Frappe 钩子清理，也不会进入目标函数。诊断 API 只允许已认证用户，
Guest 通过统一错误服务得到可追踪但不含敏感信息的 401 响应。
