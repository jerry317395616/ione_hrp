# ADR-0006 使用应用领域服务和加密响应快照实现写入幂等

## 背景与问题

`ione_hrp` 的业务写入需要统一处理权限、审计、事务、异常和重试。仅把“设置最终状态”
设计为天然幂等，不能证明客户端超时后的重试是否再次执行了副作用；只在 Redis 或进程
内缓存结果，又无法跨重启和多 worker 保持一致。直接修改 Frappe 请求处理器会破坏锁定
上游边界。

现有 `PLT-009` 模块启停 API 没有强制幂等键。将它迁移到新契约会要求调用方补充
`Idempotency-Key`，因此这是高风险且破坏性的 API 加固。

## 决策驱动因素

- 一个自研 App 内所有模块需要相同的写入执行语义。
- 权限必须在创建幂等记录前校验，避免泄露服务和请求状态。
- 业务写入和幂等结果必须在同一数据库事务内成功或回滚。
- 服务不能提交由 Frappe 请求或任务拥有的事务。
- 重试必须跨 worker、进程重启和应用更新可用。
- 原始幂等键、请求正文和明文响应不得落库或进入日志。
- 不修改 Frappe、ERPNext 或 HRMS 源码。
- 标准财务和库存过账仍必须调用 ERPNext 标准控制器。

## 备选方案

1. 只依赖最终状态：实现简单，但无法覆盖创建、过账、外部调用等非状态设置命令。
2. 使用 Redis 或进程缓存：性能高，但不是业务事务的一部分，重启、驱逐和多节点会丢失。
3. 修改 Frappe 核心请求层：覆盖面大，但违反上游锁定和 Press 可升级边界。
4. 在 `ione_hrp` 建立模板方法领域服务和持久化幂等 DocType：可由单 App 统一复用，
   使用原生事务和 Site 加密能力，不修改上游。

## 决策

采用方案 4。

`DomainService` 固定执行权限、领域校验、请求规范化、幂等预留、领域操作、响应快照、
审计和异常映射。命令必须提供 8 至 140 字符的受控 ASCII 幂等键。服务和键生成确定性
记录名，请求载荷生成 SHA-256 指纹。同键同参重放完成结果，同键异参返回
`IONE-CORE-0007`。

新增内部 DocType `HRP Service Idempotency`。它只保存键哈希、请求指纹和使用 Site 密钥
加密的规范化响应快照，并保存响应指纹用于重放校验。记录仅允许系统管理角色只读，
应用通过受控服务写入。

服务在幂等预留前建立数据库 savepoint，任何失败回滚业务写入和预留记录；服务禁止调用
`frappe.db.commit()`，最终提交归外层 Frappe 请求或任务事务所有。外部副作用不纳入本
基础实现，必须通过后续 outbox 或补偿设计扩展。

## 后果

所有新的写 API 都必须提供幂等键并采用领域服务 facade。API 可以安全重试，但会新增一
条有生命周期的内部记录，并依赖 Site 加密密钥进行重放。响应快照有 256 KiB 上限，
请求和响应必须是确定性 JSON 对象。

`PLT-009` 从状态式幂等升级为键式持久化幂等，旧客户端在没有请求头时得到受控 400。
调用方必须在部署本版本前完成适配。

## 验证与退出条件

纯单元测试覆盖服务定义、规范化、大小限制、哈希和公开结果。锁定 Bench 集成测试覆盖
权限、成功执行、重放、冲突、缺失键、加密快照、异常回滚和真实 HTTP 请求头。仓库门禁
禁止领域服务提交事务，要求三份 API 契约一致，并验证 DocType 不保存原始键或请求。

当锁定 Frappe 版本提供并验证了等价的标准持久化幂等机制时，可以用新的 Accepted ADR
替代本决策。

## 迁移与回滚

`bench --site <site> migrate` 同步新 DocType，不需要数据补丁或 Fixture。发布前先备份
Site 数据库和加密密钥。回滚应用代码前必须确认没有旧客户端依赖响应重放；保留
`HRP Service Idempotency` 表直到所有有效记录过期，不能直接删除生产数据。若恢复旧
`PLT-009` 契约，应先通过独立兼容版本和新 ADR 审批。

## 安全与合规

权限在幂等预留前校验；DocType 只授予系统管理角色只读权限。原始幂等键、请求正文和
明文响应不持久化，日志也不记录这些内容。响应使用 Site 密钥加密并以 SHA-256 验证完整
性，数据库备份必须和 Site 私钥按同一恢复点保护。该技术记录不得存放患者、员工、供应商
或凭证数据；包含此类数据的领域服务还必须遵守对应数据域的最小化、保留和访问审计规则。
