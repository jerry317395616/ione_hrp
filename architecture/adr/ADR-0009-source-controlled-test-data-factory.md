# ADR-0009 使用源码注册且仅限非生产的测试数据工厂

## 背景与问题

HRP 后续数百个领域任务需要可重复的主数据、交易前置条件、权限主体和性能场景。各测试
自行插表会复制依赖逻辑、绕过控制器并产生不可清理数据；从生产脱敏复制仍可能泄露患者、
员工、供应商和财务信息。通用“传 DocType 和 JSON”接口又等同于远程任意数据库写入口。

## 决策驱动因素

- 数据必须确定性、可重放、可组合并能按依赖顺序生成。
- 任何生成动作必须在生产写入和幂等预留前失败关闭。
- 不得使用生产快照、真实个人信息或日志中的种子/记录明细。
- 写入必须复用标准 DocType/ERPNext 控制器和 COD-011 领域服务。
- 场景变化必须经 Git、PR、测试和 ADR/变更治理。
- 不建立另一个自研 App，也不修改上游核心源码。
- 工厂不拥有事务提交，不提供危险的通用级联删除。

## 备选方案

1. 每个测试直接创建记录：启动快，但依赖、命名、权限和清理不可统一。
2. 从生产备份脱敏复制：数据真实，但重放慢，脱敏遗漏和合规风险不可接受。
3. 提供任意 DocType/字段的 HTTP 工厂：灵活，但会成为高权限通用写后门。
4. 源码注册的版本化场景 + 静态 builder + 受管非生产环境门禁。

## 决策

采用方案 4。

场景由 `test_data_scenarios.json` 声明稳定身份、版本、角色、允许环境和步骤 DAG。JSON
不能包含导入路径、SQL 或表达式；builder 必须存在于应用内静态白名单。生成只允许受管
`development`/`test`，同时要求测试接口开启、仅合成数据、非公开访问和外部集成关闭。

写入入口是 `HRP Foundation` 公共 service facade，使用 COD-011 的角色、savepoint、
加密持久化幂等和审计。HTTP 只暴露 `PLT-017` 只读契约，不暴露生成或删除。初始场景仅
创建禁用的无个人信息标记，领域数据由对应 COD 增量登记。

## 后果

测试数据从临时脚本变成可审查的版本化契约，失败可整体回滚，重复请求不会产生重复记录。
新增场景需要少量源码和测试，灵活性低于任意 JSON 工厂，但显著降低生产误写和越权风险。

持久非生产数据不做逐记录清理；环境重建成本高于通用删除，但不会误删关联业务数据。
性能基线任务可以在同一机制上增加受控规模参数，但必须另行限制最大记录数和资源预算。

## 验证与退出条件

纯单元测试验证严格模式、DAG、危险 profile、PII 声明、builder 白名单、种子和确定性
标识。锁定 Frappe/MariaDB 集成测试验证真实控制器、权限先行、环境先行、幂等、冲突、
部分失败回滚、脱敏审计和 HTTP 权限。仓库门禁固定无 HTTP 写、无任意 DocType 输入、
无直接提交和无生产 profile。

若锁定 Frappe 以后提供等价的场景级安全工厂，可用新 ADR 替代；迁移必须保留场景身份、
种子语义和环境门禁。

## 迁移与回滚

本决策不新增生产 DocType、表、Fixture 或 Patch。部署只增加 Python、JSON 和只读 API
元数据。回滚提交即可；非生产合成数据通过重建对应 replaceable Site 清除，禁止在生产
执行数据删除或从非生产恢复数据库。

## 安全与合规

只有系统管理员角色可生成或读取契约。注册表强制 `contains_personal_data=false`，输入
不支持任意字段，审计不记录种子、数据集 ID、记录名或业务载荷。生产、未受管、公开、
外部集成开启及配置漂移环境均失败关闭。现有数据库账户权限、备份加密和运维访问审计仍
由平台安全策略负责。
