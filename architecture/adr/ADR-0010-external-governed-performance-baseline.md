# ADR-0010 使用外部受控执行器建立源码化性能基线

## 背景与问题

HRP 需要可比较的响应时间、错误率和吞吐基线，并最终承载预算并发、百万库存查询、三单
匹配和事务消息故障恢复测试。若从 Frappe Web 请求或后台任务内发起压测，会占用被测系统
自身 worker、绕过基础设施容量控制，并可能误打生产。临时命令又容易漂移阈值、泄露
凭据或只留下不可复核的截图。

## 决策驱动因素

- 性能预算、负载规模和响应契约必须版本化、可审查、可重复。
- 请求总数、VU 和时长必须有源码硬上限。
- 生产、公开、未受管、外部集成开启环境必须在发压前失败关闭。
- 凭据不得进入命令行、日志、审计、Git 或结果制品。
- 基线结果必须由压测引擎和独立评估器双重判断。
- 不建立第二个 App，不修改 Frappe、ERPNext 或 Frappe HR。
- 不把尚未交付的领域容量场景伪装为完成。

## 备选方案

1. 在 Frappe API 内执行并发请求：部署简单，但自测 worker、事务和超时模型失真。
2. 手写 Python 线程压测器：依赖少，但指标、调度和阈值语义需要自研维护。
3. 只保存人工测试表格：没有可执行契约，难以发现配置漂移和回归。
4. 源码注册表 + 只读站点门禁 + 外部 k6 + 独立 Python 评估器。

## 决策

采用方案 4。`performance_baselines.json` 定义只读场景、smoke/baseline/load 固定迭代
档、阈值及全局上限。k6 使用 `shared-iterations` 执行固定总请求数，以自定义
Counter、Rate 和 Trend 强制请求数、吞吐、错误率、检查率、p95 和 p99。

Frappe 的 `PLT-018` 只返回注册表、锁定 k6 `2.1.0` 和环境许可，不启动压测、不接收结果、不写数据库。
外部 Python 包装器验证目标 URL，从环境读取临时 Token，比较本地/目标注册表 SHA，调用
k6，并对脱敏汇总进行第二次严格评估。

## 后果

性能基线成为可审查的代码，资源消耗有上界，注册表漂移和危险环境不能静默执行。需要在
执行机安装 k6，并由运维提供隔离 test 环境和短期 Token；常规单元/集成 CI 只验证契约，
实际容量测试在生产等价测试环境单独运行。

初始场景只覆盖平台只读链路。TST-0133 至 TST-0147 必须等相关领域模型和一致性断言落地
后逐项扩展，COD-015 不声称已完成这些未来容量场景。

## 验证与退出条件

纯单元测试验证严格模式、资源上限、只读路径、环境白名单、阈值可达性、结果身份和全部
失败指标。锁定 Frappe/MariaDB 集成测试验证权限先行、环境许可、危险环境拒绝、重复读取
无写入、脱敏审计和真实 HTTP 成功/访客拒绝。仓库门禁固定 API GET-only、外部执行、
无命令行 Secret、无 TLS 绕过、无生产 profile 和无上游源码修改。

若未来采用受管理的分布式 k6 Operator，可用新 ADR 替换本地进程编排，但必须保留同一
场景身份、注册表 SHA、资源硬上限、环境门禁、凭据规则和结果模型。

## 迁移与回滚

不新增 DocType、表、Fixture、Workspace 或 Patch。回滚应用提交即可；站点数据库无性能
记录需要迁移或删除。外部报告由制品保留策略独立清理，临时 API Token 立即吊销。

## 安全与合规

只压无个人信息的 GET 场景。目标只允许受管理 development/test，HTTPS 不能携带用户、
密码、查询或片段，loopback 以外拒绝 HTTP。报告和审计不含目标 URL、用户、API Key、
Secret、响应正文或站点名。生产 Press Site 永不作为本任务执行目标。
