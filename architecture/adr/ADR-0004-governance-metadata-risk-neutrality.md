# ADR-0004 必需变更元数据不参与实质风险定级

## 背景与问题

COD-008 要求每个 PR 必须修改变更记录、任务文档和 backlog 行，同时风险规则
又把 `changes/**` 作为高风险治理控制。结果是任何普通业务变更仅因提交必需
元数据就被升级为高风险并强制新 ADR，形成“为了登记变更而必须决策”的自循环，
不能真实表达代码、数据、权限和接口的实质风险。

## 决策驱动因素

- 所有任务仍必须提交三项治理元数据且接受完整性与覆盖范围校验。
- 风险等级应由实质代码、Schema、权限、API、依赖和架构路径决定。
- 修改其他任务记录、治理策略、ADR 或门禁实现仍必须失败关闭。
- 变更摘要必须继续包含全部文件，不能从审计哈希中删除元数据。

## 备选方案

1. 每个 COD 都创建 ADR：流程最严格，但 ADR 会退化成任务日志并失去决策价值。
2. 从风险策略删除所有治理路径：避免自循环，但真实治理控制修改也会漏检。
3. 只在风险匹配阶段排除当前任务必需的三项元数据，其他校验和摘要仍覆盖全部
   文件：既避免自循环，又保留治理控制保护。

## 决策

采用方案 3。`assess_changed_paths` 继续要求并校验当前任务的
`changes/COD-XXX.json`、`backlog/COD-XXX.md` 和 `backlog/backlog.csv`，但
风险规则只匹配其余实质路径。全部路径仍进入覆盖校验、单任务约束和确定性
变更摘要。ADR、策略、CI、其他任务记录或治理实现的修改不属于豁免范围。

## 后果

普通服务和 API 任务可按实际路径定为 medium，Schema、权限和架构变更仍按
现有规则升级。治理元数据缺失、路径未覆盖或跨任务修改仍立即失败。维护者需要
理解“风险中性”不等于“不受治理”，三项文件仍是每个 PR 的硬性契约。

## 验证与退出条件

单元测试必须证明只有三项当前任务元数据被风险匹配排除，仍进入摘要并保持
必填；修改 ADR、策略、CI 或其他任务记录继续升级或拒绝。真实 PR 和 main
推送必须通过差异门禁。若未来按语义而非路径进行可靠风险分类，可由新 ADR
取代本决策。

## 迁移与回滚

无数据库迁移。回滚会恢复旧风险匹配行为，但会再次导致每个任务强制 ADR；
因此只能通过后续 COD 和新 ADR 回退，不改写本 Accepted ADR。

## 安全与合规

豁免不适用于权限文件、上游锁、Schema、迁移、CI、ADR 或治理策略。变更摘要
仍覆盖元数据，攻击者不能通过把实质路径写进任务文档来降低风险。路径规范化、
单任务限制、删除 ADR 禁止和 Accepted ADR 校验保持不变。
