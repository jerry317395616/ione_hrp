# ADR-0020 使用修订锁定且不可转委托的审批委托

## 背景与问题

医院审批人在休假或临时分工期间需要转移审批责任。通用用户代理、角色复制或永久改写审批矩阵会扩大
权限、失去原责任人证据，并可能在矩阵修订后继续使用过时授权。

## 决策驱动因素

- 委托不能扩大目标 DocPerm 或组织数据范围；
- 必须绑定真实审批责任、矩阵修订和有限有效期；
- 自我委托、重叠、转委托链和循环必须默认拒绝；
- 创建、撤销、解析和过期都必须可审计且可重放；
- 回滚不得删除生产委托数据或现有业务单据。

## 备选方案

1. 临时给受托人复制角色：简单，但范围过大且无法关联具体矩阵步骤。
2. 修改审批矩阵中的审批人：会改变所有历史和未来业务上下文，审计证据不足。
3. 使用通用 User Permission：不能表达矩阵修订、步骤和有效期。
4. 新建受控委托记录，锁定矩阵修订和范围，并在审批解析阶段替换责任人。

## 决策

采用方案 4。委托人必须拥有目标矩阵步骤；受托人必须同时拥有目标写权限和同等组织写范围。委托最长
366 天且不允许转委托。委托锁定矩阵修订号和策略摘要，矩阵修订后自动停止适用。生命周期写入只能由
幂等领域服务执行，DocType 直接写入和删除全部拒绝。

## 后果

审批解析得到明确的原审批人、受托人和委托记录证据，业务模块无需复制授权逻辑。配置冲突或权限漂移
会阻止审批解析并要求修复，不会静默回退。管理员需维护有效期并通过报表关注即将到期记录。

## 验证与退出条件

- 运行 DocType、蓝图、字段目录、API 目录和 OpenAPI 完全一致；
- 纯测试覆盖有效期、确定性摘要、步骤替换和歧义；
- Frappe 测试覆盖幂等、权限、组织范围、重叠、撤销、矩阵修订、调度和 HTTP；
- 任意直接写入、转委托链、循环或权限提升均被服务或仓库契约拒绝。

## 迁移与回滚

部署前完整备份 Site。迁移新增委托表和两个复合索引，并同步角色与工作区。回滚应用提交时保留委托表；
旧版本不消费记录，不执行破坏性删除。紧急处置通过撤销委托或停用矩阵完成。

## 安全与合规

System Manager 与 HRP System Manager 可管理全部委托；HRP Department Manager 只能管理自己的委托；
HRP User 只能读取与自己相关记录；HRP Auditor 只读全部记录。审计日志不保存用户和组织原值。
