# COD-004 配置 Ruff、Pyright、ESLint、Prettier

## 设计依据

- `AGENTS.md`
- `Definition_of_Done.md`
- `architecture/quality_tooling.md`
- `pyproject.toml`
- `package.json`

## 交付

- Ruff `0.15.9` 精确固定，统一 lint/format 范围并收紧历史全局忽略。
- Pyright `1.1.411` 覆盖应用、脚本和测试。
- ESLint `10.8.0` 使用 flat config，支持 Frappe JavaScript、TypeScript 和
  Vue 文件。
- Prettier `3.9.6` 负责前端源码、Frappe JSON 和质量配置。
- `package-lock.json` 固定完整 Node 开发依赖树，`.npmrc` 强制精确保存。
- `scripts/quality.py` 提供跨平台只读门禁；`quality.sh` 不再静默跳过工具。
- 仓库契约验证配置存在、版本精确、锁文件一致、Pyright 未关闭和质量入口
  不可绕过。

## 适用面

本任务是工程基线，不新增 DocType、Workspace、Fixture、写服务或业务 API，
不修改数据库，也不修改 Frappe、ERPNext、Frappe HR 源码。权限、数据范围、
业务审计和业务幂等不适用。质量执行本身只读且可重复。

## 异常路径

自动化测试覆盖：

- npm 缺失或 `NPM_BIN` 无效；
- 任一质量步骤失败时立即停止并返回非零；
- 配置文件缺失；
- Node 依赖使用范围版本或锁文件漂移；
- 质量步骤顺序确定且重复构建计划一致；
- 只读执行不修改任何质量配置文件。

## 验证

```bash
python scripts/quality.py
npm audit --audit-level=high
git diff --check
```

隔离 Bench 还需使用锁定 Frappe、ERPNext、Frappe HR 依赖执行：

```bash
python -m pyright --project apps/ione_hrp/pyrightconfig.json
bench --site <test-site> run-tests --app ione_hrp
```

## 升级与回滚

本任务只有源码格式与开发工具配置变化，无数据库迁移。回滚到上一应用提交
即可恢复；不需要删除 Module Def、DocType 或业务数据。Node 依赖回滚必须使用
对应提交的 `package.json` 和 `package-lock.json` 后重新执行 `npm ci`。
