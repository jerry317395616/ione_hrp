# COD-024 实现访问范围和数据权限查询

## 任务信息

- 阶段：1-核心闭环
- 模块：HRP核心平台 / HRP Workflow Authorization
- 优先级：P0
- 前置任务：COD-023
- 风险：跨模块数据隔离、权限提升、组织版本和运行站点迁移

## 验收映射

| 验收项 | 实现 | 自动化证据 |
| --- | --- | --- |
| 访问范围模型 | `HRP Access Scope`、`HRP Access Scope Member` | 纯契约、元数据与引用验证测试 |
| 默认拒绝 | 无范围、无基础 DocPerm、字段不兼容均拒绝 | 决策和真实权限 helper 测试 |
| 组织层级 | 法人、医院、组织单元及已发布下级展开 | Nested Set 集成测试 |
| API | `CORE-001` 只读解析接口 | 真实 HTTP、非法操作和跨用户限制测试 |
| 列表与单据权限 | 组织四类 DocType 统一查询和单据 helper | SQL 条件与单条匹配测试 |
| 审计 | 决策摘要、不记录用户和范围值 | 日志脱敏测试 |
| 迁移与工作区 | 三类索引、四个应用自有 Workspace 强制同步 | 重复迁移和默认工作区映射测试 |

## 实现范围

- 将设计目录中的通用访问范围占位模型替换为运行模型；
- 管理员在中文 Desk 页面维护范围和用户授权；
- `CORE-001` 返回结构化过滤组，禁止任意 SQL、脚本和字段配置；
- 医院、组织版本、组织单元和组织映射接入统一权限 helper；
- 修复标准 Workspace 源码更新因站点记录时间较新而不生效的问题。

## 非目标

- 不在 COD-024 中实现审批矩阵、职责分离或委托；
- 不提前实现仓库、供应商、银行账户、项目组合等领域专用维度；
- 不用数据范围替代 Frappe 角色和 DocPerm；
- 不修改 Frappe、ERPNext 或 Frappe HR 核心源码。
